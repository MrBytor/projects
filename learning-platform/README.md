# Local teaching platform

Custom Django application built around the existing academic website. No WordPress or WordPress plugins are executed.

## GitHub source backup

This repository contains the public website, LMS source, migrations, tests and local launcher. On another Windows computer, install Python, clone the whole repository, and run `Start Teaching Platform.cmd`. Keep `academic-preview` and `learning-platform` together; the LMS reads the public course outlines and question bank from its sibling directory.

Accounts, student records, saved results, teacher-edited folder order/content, private uploads and generated previews are not stored in Git. They remain under `%LOCALAPPDATA%\EurasiaTeachingPlatform\data`. A new computer starts with a fresh database and seeded course structure unless that private data is restored separately. The GitHub copy is a source-code backup, not a complete backup of the current learning records and materials. Publishing this source does not start the Django application on GitHub Pages.

The launcher requires Python on PATH. Installed desktop PowerPoint is used to generate presentation previews; the app can start without it, with unavailable previews reported by the launcher.

## Start and sign in

Double-click `Start Teaching Platform.cmd` in the parent `website` folder. Keep its terminal open while using the app, and open http://127.0.0.1:8765/. If a server is already running on that port, use it instead of starting a second copy. Stop the server with Ctrl+C in its terminal.

On Windows the runtime, database and secrets live in `%LOCALAPPDATA%\EurasiaTeachingPlatform`, outside OneDrive and Git. Initial test credentials are in `data\local-credentials.txt` there. `teacher-demo` and `student-demo` have independently generated passwords. Existing accounts and passwords are preserved on subsequent starts. Passwords in the database are hashed; the local credentials file is only for initial development access. Change passwords from the account navigation when desired.

The teacher account can create student accounts, edit names/emails/majors/teaching groups, change course access, and assign question-bank tests to everyone in a course. The student account can access enrolled courses, save Statistics practice, and complete homework tests. Switch accounts using the permanent **Sign out** control above the main menu. The header shows the signed-in name, Teacher/Student role and Dashboard link throughout the local site.

Use the `http://127.0.0.1:8765/` version for accounts. Opening the HTML files directly or visiting GitHub Pages opens the static website, which does not share this app's login session.

## First working slice

- Teacher and student dashboards, login/logout, optional 14-day remembered sessions and password changes. The login follows the Academic reference's wide photo banner and centred card. The dashboard uses a sidebar, summary cards and completion tables in the existing site colours.
- Separate dashboard pages: Overview (`/`), Assigned tests (`/assigned-tests/`), teacher Students (`/teacher/students/`), student My courses (`/my-courses/`) and student Learning progress (`/learning-progress/`). The overview contains summary counts, live course cards, a small teacher gradebook preview or student next steps/results; navigation opens another page instead of scrolling to sections. The teacher menu omits My courses, and practice is reached through course pages.
- Three courses backed by the existing static content.
- Teacher-owned course enrolments and student account creation. The Students directory shows name, username, major, teaching group, email, course checkboxes and test-completion counts. Filter by major, teaching group, enrolled course and coursework status (overdue, outstanding, completed, no tests or no courses). Selecting a course scopes completion counts/status to that course. Pages show 25 students and retain filters. Save access updates only the current teacher's courses; Edit details changes name/email and teacher-specific major/group without changing account roles. Existing major/group values remain blank until entered; missing details are labelled rather than fabricated.
- Registered students remain in their teacher's directory even when all courses are unchecked. The upgrade registers existing student/teacher relationships from enrolments. Removing enrolment blocks that course's assigned homework/tests and saved practice, and preserves saved attempts for later re-enrolment. Course descriptions and class information remain public. Demo setup on subsequent starts respects saved enrolment choices.
- Assign Statistics tests from the existing bank: filter by week/difficulty, search titles/topics, preview prompts and select 1–50 questions. Corporate Finance and Project Management do not yet have banks and cannot be selected for tests.
- Each test stores a snapshot of its prompts and marking rules. It automatically appears for every student enrolled in that course, including students enrolled after publication. Test recipients are determined by current course enrolment.
- Assigned tests use compact rows grouped by course, teaching week and class/session, with 20 tests per page. Filters cover course, week, class and completion status; order by course/week/class, newest or deadline. Students also have Not started/In progress filters. Set optional week/class labels when creating a test, or use Organise on an existing test without changing questions or grades. A single question-bank week is inferred when no teaching week is selected; mixed-week tests can be labelled manually. The upgrade applies the same inference to existing tests. List summaries use database counts and defer question snapshots instead of loading every test's roster.
- Explicit Start, Save progress, Resume and Submit actions. Submission requires valid answers to every part. The server awards one point per wholly correct question. A final submission is immutable; there are no retakes in this version. Completion and score are distinct: a fully answered test can be completed with a low score.
- Teacher results combine completed/enrolled in one summary card, plus average percentage and average points. Averages use submitted scores from currently enrolled students, including zero scores; unfinished tests are excluded and an empty average shows a dash. Completion rosters show Not started / In progress / Completed, score, completion time and overdue/late labels, with status filtering and 25 students per page. Summary cards always describe the whole class regardless of roster filters/page. A student's profile combines assigned-test status with practice evidence. The directory includes the teacher's registered students plus students enrolled in the teacher's courses.
- Earlier written-homework records and legacy URLs remain intact for access to old work; the new dashboards use tests only. No files are requested from students.
- Statistics practice checked against the question bank on the server, with database persistence. A session/question pair retains its first valid attempt; retries update the latest answer without changing the first result.
- Teacher Gradebook (`/teacher/gradebook/`) shows one course as a student × test matrix, with course/week/major/group filters. Students are paged 25 at a time and test columns 12 at a time. Completion and average percentages include all matching tests across column pages. Drafts and missing grades are excluded from averages; zero scores count. Click a test to open its results roster or a student to open their progress.
- Students have To do (`/my-tasks/`) and Calendar (`/calendar/`) pages. To do contains only outstanding work from current enrolments, ordered by deadline, with course/status filters and Start/Resume links. The dashboard previews the next five tasks. The monthly calendar includes completed and outstanding test deadlines in China time (UTC+8); work without a deadline remains in To do.
- Learning progress lists Statistics's 59 objectives and Corporate Finance's 64 published class objectives, with course/evidence filters and 20 objectives per page. Submitted homework answers are evaluated against each frozen question's objective mapping alongside saved first practice attempts. Field mappings allow correct homework parts to contribute to their secondary objectives without changing the overall question grade. Unknown/missing legacy answers produce no fabricated evidence. Repeating one question does not count as several distinct questions. Suggestions link to the lesson and select relevant practice questions. “Consistent results” requires at least three distinct questions with no incorrect or assisted observations; it is evidence, not a claim of mastery. Help flags and practice session IDs originate in the browser; this is not a proctored assessment system. Finance practice requires a future bank; Project Management objectives still need mapping.
- Teacher student import (`/teacher/students/import/`) accepts UTF-8 CSV (comma/semicolon/tab) and Excel `.xlsx` with a preview and an explicit confirmation. Blank templates are downloadable. Required columns: `username`, `name`; optional: `email`, `major`, `teaching_group`, `courses` (course slugs separated by `|`). Limits: 1,000 students, 2 MB, first worksheet only; formulas must be pasted as values. Validation catches duplicate usernames/emails, invalid fields, foreign accounts and unavailable courses. Confirmation revalidates and applies all rows in one transaction. Listed courses are added; existing enrolments, passwords and saved work remain intact, and blank optional fields preserve current values. New accounts receive generated passwords shown once after import, with a local CSV download. Save those login details privately and give each student their own credentials. Import previews expire after 30 minutes; passwords are never stored in preview sessions. No email invitations are sent.
- CSRF protection, escaped user content, course/teacher access checks, login throttling and HTTP-only session cookies.

The public HTML files remain usable on GitHub Pages. Local Django HTML responses receive a shared account-aware header and practice-saving bridge. Home, Courses, Publications, About Me, all three course outlines and their class pages are readable without login. The public Courses menu opens the public catalogue. Inside the LMS, Courses opens enrolled subjects for students and owned teaching subjects for teachers. Interactive Statistics practice, assigned homework/tests, account dashboards and saved progress require sign-in; coursework and saved practice remain scoped to enrolment. Local course navigation uses full page requests, refreshing session state and CSRF tokens; returning from another tab also checks the active account. Dynamic HTML uses no-store caching. Practice saves include the account ID captured at page load, so switching accounts cannot save stale attempts into someone else's account.

The shared practice UI emits a small event; it makes no account requests on the static public site because the bridge is absent there. Assigned-test HTML does not include answer keys, hints or solutions, and grades are computed on the server. However, the same question bank remains publicly available for practice; these are homework tests, not secret or proctored exams.

## Try the test workflow

1. Sign in as `teacher-demo`. Use **Assign a test**, choose questions and optional week/class labels, and publish. Open **Results** from Assigned tests to see both started and unstarted students.
2. Sign out and sign in as `student-demo`. Open Assigned tests, start a homework test, answer a few questions and save. Resume from Assigned tests, finish and submit.
3. Sign back in as the teacher. The completion roster now shows the student's score and submission time.

`seed_demo` adds a labelled five-question Statistics sample without changing passwords or student work. The database migration adds test tables without deleting old homework.

## Data and development

Backend: Django 5.2 LTS. Local database: SQLite. Config is deliberately local-only (`127.0.0.1` / `localhost`, port 8765, development server). `TEACHING_DATA_DIR` can select another private data directory. The default database is `%LOCALAPPDATA%\EurasiaTeachingPlatform\data\learning.sqlite3`; do not commit it, the secret key, or demo passwords. For a consistent backup, stop the server and copy the data directory to a private backup destination.

Install requirements in an isolated Python environment. On this computer it is `%LOCALAPPDATA%\EurasiaTeachingPlatform\venv`. Commands from this folder:

```powershell
& "$env:LOCALAPPDATA\EurasiaTeachingPlatform\venv\Scripts\python.exe" manage.py migrate
& "$env:LOCALAPPDATA\EurasiaTeachingPlatform\venv\Scripts\python.exe" manage.py seed_demo
& "$env:LOCALAPPDATA\EurasiaTeachingPlatform\venv\Scripts\python.exe" manage.py test
```

Before internet deployment: use a production application server and HTTPS, production settings/secrets and secure cookies, choose a production database (PostgreSQL is a candidate), configure backups and password recovery, and test concurrency and browser behaviour. This prototype has no email recovery/invitations, test retakes or audit/version history. GitHub Pages cannot run this backend. No backend deployment has been performed.

Validation: 178 Django tests cover public browsing, account/course/teacher permissions, CSRF, grading and frozen snapshots, saved drafts and immutable submissions, directories and filters, pagination and bounded query counts, gradebook matrix averages, calendars, learning objectives, student imports, editable folders/materials, upload validation, inherited visibility, legacy access paths, and preview jobs. All 21 JavaScript tests pass (14 Statistics, 2 credential downloads and 5 slide viewer tests). The material dialogs also pass an isolated browser smoke test using synthetic data and intercepted requests; the running localhost browser session has not been accessed.

## Logged-in LMS layout (10 October 2026)

The public site retains its Academic theme. Authenticated pages use a compact navy header, persistent account/Sign out controls, a sidebar, course tiles and a responsive workspace. Teacher/student navigation still opens separate pages. Courses at `/courses/<slug>/` use the published module/class outlines; compact material rows omit descriptions, while objectives belong to the lesson pages. Course pages link to assigned tests, current course members/gradebook or personal progress. Teachers now have a calendar of their owned courses' test deadlines.

Lesson pages at `/courses/<slug>/classes/<key>/` display actual presentation previews with numbered thumbnails, previous/next controls and fullscreen, followed by up to four existing bank questions. **Save progress** persists drafts without grading; **Check answers** checks every part on the server and records formative evidence. Retries preserve the first result. These checks never change assigned-test grades. Teachers can inspect lessons without creating student attempts. Current enrolment/ownership is checked for lesson pages, slides, downloads, practice and saves; switched accounts cannot save old lesson forms. Lessons retain frozen practice questions once started.

All 12 existing Statistics PPTX files have previews (612 slides), exported directly by PowerPoint as PNG images; no PDF conversion is used. The original presentations stay unchanged and downloadable; previews omit animations and speaker notes. Handouts, spreadsheets and shared vocabulary remain available as downloads. Other classes show the real published descriptions/objectives and state when materials have not been added. Only classes with matching Statistics bank questions have quick checks. Corporate Finance and Project Management do not yet have question banks.

The viewer uses a bounded slide frame, a separately scrolling thumbnail rail and a compact toolbar. Answer controls align on shared rows, with help text and validation errors below them. Slide-specific question checkpoints and their teacher settings are planned for a later step; current quick checks remain attached to the whole lesson.

Derived previews live privately under `%LOCALAPPDATA%\EurasiaTeachingPlatform\data\slide-previews`, keyed by the source SHA-256. The local launcher prepares missing/stale previews with installed PowerPoint in a read-only background export; it does not close or touch an existing PowerPoint session. Close PowerPoint before manually preparing new previews:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\render-presentations.ps1
```

The LMS migration only adds a lesson-practice table. A verified private database backup was taken before applying it. Browser layout verification remains pending because access to localhost was denied earlier; server-rendered page, permissions, scoring and persistence checks pass in isolated tests.

## Editable folders and materials (10 October 2026)

Authenticated course materials now live in a database-backed tree. Modules and classes are seeded as ordinary folders: teachers can add subfolders at any level, rename, recolour, reorder, move, and publish/hide them. The one-time `seed_content` import preserves subsequent teacher edits and retains the original class lesson/practice links. The public course pages remain the source of the initial outline, not the editable LMS state.

Click a folder's icon, name or arrow to expand its contents inline on the course page. Nested classes and subfolders work the same way; files, lessons and tests retain their own viewers. All material rows use compact icons and titles with inline metadata; descriptions remain saved and are shown on material detail pages rather than in the list. Expanded folders are remembered for the current account and course in the browser session. Each open folder has its own Add materials menu. Saving or moving material returns to its parent in the course tree, and links back from a lesson/material reopen the matching folder and its ancestors. Older direct folder URLs remain supported.

Teachers can drag a folder icon higher or lower within its current parent; its children and expanded state stay with it. A drop marker previews the destination and the order saves automatically. The same icon supports Alt + Up/Down, and the existing Move up/Move down menu remains available without JavaScript. Moving between different parent folders still uses Move to folder. Reordering checks account, course ownership, CSRF, the full sibling set and the previously displayed order; changed or stale lists are rejected without overwriting another edit. Students see the saved course order without editing controls.

Folder ordering is covered by ten server tests and `tests/content-order.browser-smoke.cjs`, using synthetic data with all requests intercepted. The browser checks exercise real mouse and touch dragging, mixed material rows, expanded nested folders, keyboard controls, pending saves, stale/network errors and student restrictions. No live course order was changed during verification.

The **Add materials** menu opens a centred in-page dialog for a folder, file/presentation, video, page, link, or quiz/test. Edit and Move use the same dialog. Server validation stays in the window, Escape/Cancel returns focus to the opener, and forms have a separate-page fallback. Descriptions/page content are plain text and escaped; rich-text editing and slide-specific questions are not implemented in this step.

New files are stored privately in `DATA_DIR/content-files` and checked against allowed signatures/extensions and a 50 MB size limit. PDF/image previews and downloads require current course access. New uploaded PPTX files trigger a hidden background PowerPoint export after the database commit; existing previews are reused by content hash. If PowerPoint is already open, files remain downloadable and missing previews are retried on the next local launch. Close PowerPoint and use `render-presentations.ps1` to retry manually. Export jobs use a mutex, disable macros, never save the presentation, and log to `DATA_DIR/slide-preview-jobs.log`.

**Add video** offers Upload video or Video link in the same dialog. Uploaded MP4/WebM files have a separate 100 MB limit (104,857,600 bytes) and container validation. They are stored privately and play in a responsive browser player with native playback, volume, seeking and fullscreen controls. The video endpoint checks current course access and inherited folder visibility on every request, streams bounded chunks, and supports single HTTP byte ranges and HEAD. Ordinary document uploads retain their 50 MB limit. No video transcoding is performed; the browser must support the codecs in the file, with MP4/H.264/AAC recommended in the form. The original file remains downloadable.

Video links support validated YouTube/Vimeo embeds and direct MP4/WebM sources. Other sites retain an external link; provider permissions, browser codec support and external availability can affect playback. Provider URLs are classified locally without fetching arbitrary URLs on the server. Switching an existing video between an upload and a link clears the obsolete database reference while retaining old private files on disk. Reference: [browser range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests).

Draft and scheduled folder visibility applies to descendants, direct file/slide URLs, legacy class pages, and linked tests. Hidden quizzes are omitted from students' assigned tests and calendars. Teacher authoring is scoped to owned courses; Django superusers may manage all courses. Submitted work and question snapshots survive material edits; an existing quiz cannot be relinked to a different test through its material editor. The Statistics bank supports creating new quizzes; the other two courses can hold files/pages/links and existing course tests, but do not yet have a question bank.

The live migration imported 96 folders, 38 file entries, and 3 existing tests across the three courses. A verified SQLite backup was saved before migration under `DATA_DIR/backups/before-editable-materials-20261010-175526.sqlite3`; account, enrolment, assignment, attempt, lesson-practice, and practice-evidence counts were unchanged after import. Database integrity and foreign keys were checked.

Repeatable UI verification lives in `tests/render_content_ui_fixture.py` and `tests/content-dialog.browser-smoke.cjs`. It creates an in-memory fixture database and intercepts all browser requests to a fake origin, including local static assets. It checks inline folder expansion, keyboard navigation, saved expansion state, folder-scoped menus, save reloads, hash links, student visibility, desktop centring, scheduled controls, modal validation/CSRF/account tokens, focus restoration, and 320px layout.

## Theme and plugin reuse assessment

Inspected the supplied `themeforest-oz9koyLf-academic-education-theme-for-wordpress.zip` (WP-Academic 2.4.3). Its `Licensing/README_License.txt` assigns PHP and integrated HTML to the GPL and the other assets to the purchased licence. Check the purchase certificate for the exact licence and end product. Do not upload the complete commercial package as a reusable public template.

| Component | Useful outside WordPress? | Decision |
| --- | --- | --- |
| Theme layout, CSS/SCSS, typography | Yes, with markup adaptation and applicable licence terms | Keep the current adapted site design and assets; new dashboard layout is authored for this app |
| Academic Core | Its templates may inform layout, but its widgets rely on Elementor/WordPress | Do not port plugin runtime |
| Codestar Framework | WordPress settings framework | Not needed for the custom teacher workflow |
| WP-SCSS | Compiler wrapper around WordPress hooks and settings | Use existing compiled CSS; a standalone compiler can be added if needed |
| Elementor and Tutor LMS | Listed as dependencies; not supplied as portable apps in the ZIP | Do not extract their account/database functionality; implement the required workflow using Django |
| Demo content and images | Useful as reference; individual asset rights must be checked | Preserve existing credited course photos and user-authored content |

The uploaded theme is **WP-Academic**, not Avada. We reuse its visual approach and applicable licensed assets; we do not copy WordPress plugins wholesale or extract their databases into this app. Their WordPress hooks, settings and dependencies would need substantial replacement. “Required” in the theme installer means required to run its WordPress version; it does not require those plugins for our independently built site, nor guarantee access to every Pro add-on.

Without WordPress we give up the ready-made Elementor visual editor, Tutor LMS's broader course/quiz administration and optional paid extensions (for example certificates), and easy installation of WordPress integrations. We also maintain our custom learning workflows ourselves. For the requested course materials, tests and progress tracking, this narrower custom application is a reasonable fit. If a broad LMS with many built-in features becomes the priority, using Tutor LMS within WordPress would usually be quicker than rebuilding that entire feature set.

For this app, custom development is justified by learning-objective tracking and the existing practice engine. A standard WordPress LMS would reach generic enrolments and quizzes faster, but the cost of disentangling its plugins is unlikely to beat building our narrower workflow. Django provides maintained authentication and database tools; we do not implement password cryptography ourselves.

References: [Envato split licensing](https://help.author.envato.com/hc/en-us/articles/360000534646-What-is-Split-Licensing-and-the-GPL), [Regular licence](https://themeforest.net/licenses/terms/regular), [Django authentication](https://docs.djangoproject.com/en/5.2/topics/auth/default/), [Django database notes](https://docs.djangoproject.com/en/5.2/ref/databases/).
